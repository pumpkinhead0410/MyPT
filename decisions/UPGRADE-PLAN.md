# TL;DR

- 목적 — [MyPT.html](../MyPT.html)을 하루 1~2회 접속해 일정·운동·식단·신체 변화 추이를 기록하고 계획을 세우는 Vite + React + TypeScript 기반 PWA 대시보드로 고도화합니다.
- 우선 해결 — 새로고침 시 상태 증발, 저녁 세트 복합 재고 미차감 및 잔여 횟수 하드코딩, 유산소 체크 초기화, 마일스톤 기준점 누적 왜곡 등 5대 결함을 수정합니다.
- 핵심 구현 — Tab 1 실시간 Now 마커·평일/주말 분리, Tab 2 타이머 삭제·7일 루틴 CRUD·대표 중량 기반 1RM 추이 차트, Tab 3 다중 재고 연동, Tab 4 다중 지표 차트·히트맵을 구축합니다.
- 검증 구분 — 타입·빌드 통과, 레거시 결함 5건 회귀 검증, `localStorage` 영속성 및 JSON 백업·복원 동작 확인을 구분해 판정합니다.
- 현재 상태 — 작업계획 확정 단계입니다. 구현은 다음 세션에서 [구현 체크포인트](../.audit/implementation.todo.md)의 Phase 1부터 착수합니다.

## 확인한 사실과 수용 기준

- 근거 — [MyPT.html](../MyPT.html)(2,743줄)은 Tailwind Play CDN과 인라인 스크립트로 작성되어 있으며 `sched`, `inventory`, `dietItems`, `workoutsByDay`, `milestones`가 메모리 변수에만 존재합니다.
- 근거 — `selectDinnerSet()`는 세트 A/B/C에 `invId` 하나만 매핑하여 부재료(닭가슴살·계란) 재고가 차감되지 않으며 `#stockTagA~C` 텍스트가 고정되어 있습니다.
- 근거 — `switchWorkoutDay()`는 호출될 때마다 전역 `isCardioDone = false`로 덮어써 요일별 유산소 완료 상태를 유지하지 못합니다.
- 근거 — `onActualWeightChange()`는 `idx === 0` 변경 시 이미 변형된 `milestones[i].targetW`에 `num - 91.1`을 누적 가산하여 기준점을 여러 번 바꾸면 목표 체중이 왜곡됩니다.
- 참고 — 사용자 수용 기준은 새로고침 후에도 모든 기록·설정이 유지되고, [의사결정 기록](2026-10-29-upgrade-decisions.md)에서 합의한 4개 탭의 추이 시각화 및 계획 기능이 오류 없이 동작하는 것입니다.
- 참고 — 고려할 실패 모드는 잘못된 JSON 백업 파일 입력, `localStorage` 파싱 실패·용량 초과, 슬라이더 시간 역전, 재고 음수 차감이며 각각 스키마 검증과 가드레일로 방어합니다.
- 참고 — 유지보수 주체는 사용자 본인(개인 프로젝트)이므로 외부 서버·DB 의존성 없이 표준 브라우저 API와 정적 빌드 구조만 유지합니다.

## 1. 기준 상태를 보존하고 프로젝트를 초기화합니다 (Phase 1)

- 참고 — 기존 [MyPT.html](../MyPT.html) 원본을 보존(또는 `evidence/baseline/`에 해시·원본 기록)하여 디자인 토큰과 초기 프리셋 데이터의 대조 기준으로 삼습니다.
- 참고 — `MyPT/` 루트에 Vite + React + TypeScript + Tailwind CSS 및 PWA(`manifest.webmanifest`) 설정을 구성합니다.
- 참고 — Apple Health 다크 테마 색상 팔레트(`surface: #161618`, `card: #1c1c1e`, `elevated: #2c2c2e`, `green: #30d158`, `accent: #fa114f`, `blue: #0a84ff`, `cyan: #64d2ff`, `orange: #ff9f0a`, `red: #ff453a`)를 그대로 계승합니다.
- 참고 — 완료 조건은 개발 서버와 `vite build`, `tsc -b`가 오류 없이 통과하고 기본 레이아웃 셸이 렌더링되는 것입니다.

## 2. 데이터 스키마와 영속성 계층을 구축합니다 (Phase 2)

- 참고 — 단일 버전 키(`mypt_state_v1`) 아래 도메인 상태를 통합 저장하고, 초기 로드 시 스키마 검증 및 기본 프리셋 폴백(Fallback)을 수행합니다.
- 참고 — `schedules`는 `weekday`(평일)와 `weekend`(주말·휴일) 두 프로파일의 시간 슬라이더 값(`leaveWork`, `workoutStart`, `workoutDur`, `dinnerStart`, `bedtime`, `wakeTime`)과 선택된 코스를 분리 저장합니다.
- 참고 — `workouts`는 월~일(`mon`~`sun`) 7일 루틴 템플릿(종목 ID, 이름, 목표 세트, 목표 횟수/RPE, 세트 완료 배열, 현재 대표 중량 `weightKg`, 대표 횟수 `reps`, 요일별 `cardioDone`)을 저장합니다.
- 참고 — `strengthHistory`는 종목별 대표 중량·횟수 갱신 이력(`date`, `exerciseId`, `weightKg`, `reps`, `estimated1RM`)을 누적 저장합니다.
- 참고 — `diet`는 비축 재고(`inventory`), 다중 재고 매핑(`ingredients: Array<{ invId, qty }>`)을 지원하는 일일 식단(`dietItems`), 저녁 간편식 세트 정의를 저장합니다.
- 참고 — `milestones`는 불변 초기 목표치(`baseTargetW`, `baseTargetWaist`, `baseTargetFat`, `baseTargetSmm`)와 실제 측정치를 분리 저장하여 기준점 변경 시 누적 왜곡을 원천 차단합니다.
- 참고 — `dailyLogs`는 날짜(`YYYY-MM-DD`)별 운동 완료율, 식단 달성률, 섭취 칼로리·단백질을 기록합니다.
- 참고 — 상단 헤더와 고정 요약 바(Sticky Summary), JSON 내보내기·불러오기·초기화 모달을 함께 구현합니다. 완료 조건은 새로고침 및 JSON 복원 후 모든 도메인 상태가 정확히 일치하는 것입니다.

## 3. 저녁 일정 다이얼과 운동 중량 추이를 구현합니다 (Phase 3)

- 참고 — **Tab 1**에 평일·주말 프로파일 전환 토글과 선후 관계 가드레일(퇴근 ➔ 운동 ➔ 식사 ➔ 취침 최소 간격 보장)을 구현합니다.
- 참고 — 24시간 원형 다이얼(SVG)과 13시간 선형 타임라인 바 위에 현재 시각(Now) 바늘·핀 마커를 렌더링하고, 현재 진행 중인 루틴 블록을 자동 포커스합니다.
- 참고 — **Tab 2**에서 기존 세트 간 휴식 타이머 위젯과 상단 타이머 요약을 제거하고, 상단 요약 바 3번째 카드에는 주간 운동 달성률 및 핵심 종목 1RM 추이 요약을 표시합니다.
- 참고 — 월~일 7일 탭과 접속 시 오늘 요일 자동 선택을 적용하고, 요일별 운동 종목·세트 수·유산소 프로토콜의 추가·수정·삭제·순서 변경 UI를 구현합니다.
- 참고 — Tab 1의 운동 코스 프리셋(60/80/100/120분) 변경 시 Tab 2의 권장 세트 수 및 유산소 목표 시간 안내가 연동되도록 연결합니다.
- 참고 — 각 운동 종목 카드에 빠른 세트 완료 체크 버튼과 함께 **'현재 대표 중량(kg) × 횟수(reps)' 1줄 갱신 컨트롤** 및 자동 계산된 **추정 1RM($\text{kg} \times (1 + \text{reps}/30)$)** 배지를 배치합니다.
- 참고 — 카드 리스트 하단에 종목 선택형 **중량 & 추정 1RM 성장 추이 SVG 차트**를 구현합니다. 완료 조건은 중량 갱신 시 이력이 누적되고 추이 차트가 즉시 갱신되는 것입니다.

## 4. 식단 다중 재고 연동과 마일스톤·히트맵을 구현합니다 (Phase 4)

- 참고 — **Tab 3**의 저녁 간편식 세트(A/B/C)와 일반 식단 항목에 다중 재고(`ingredients`) 차감·복원 로직을 적용합니다.
- 참고 — 각 간편식 세트 카드의 잔여 횟수를 연결된 재고 품목들의 $\min(\lfloor \text{count} / \text{qty} \rfloor)$로 동적 계산하여 표시합니다.
- 참고 — 일일 식단 체크리스트 항목과 비축 재고 품목의 추가·수정·삭제·일괄 선택 삭제 기능을 구현하며, 수분 섭취 트래커는 포함하지 않습니다.
- 참고 — **Tab 4**의 추이 차트에 **체중(kg) / 허리둘레(cm) / 체지방률(%) / 골격근량(kg)** 탭 전환을 추가하여 목표 곡선 대비 실제 측정 궤도를 시각화합니다.
- 참고 — 11주 마일스톤 테이블의 스텝퍼 및 직접 입력 시 오차 배지와 상단 고정 요약 바가 즉시 동기화되도록 구성합니다.
- 참고 — 일자별(`dailyLogs`) 운동·식단 달성도를 보여주는 **히스토리 캘린더(히트맵)** 카드를 구현합니다. 완료 조건은 식단 체크 시 다중 재고가 정확히 증감하고 4대 지표 차트와 히트맵이 정상 렌더링되는 것입니다.

- 참고 — 레거시 결함 5건(새로고침 증발, 복합 재고 미차감·잔여 횟수 하드코딩, 요일별 유산소 상태 초기화, 마일스톤 기준점 누적 왜곡, 상단 요약 정적 문구)이 모두 해결되었는지 시나리오별로 검증합니다.
