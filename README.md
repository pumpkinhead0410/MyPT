- 문서 — [고도화 작업계획](decisions/UPGRADE-PLAN.md)과 [의사결정 기록](decisions/2026-10-29-upgrade-decisions.md)을 프로젝트 내부에서 관리합니다.

- 현재 상태 — 기준 파일인 [MyPT.html](MyPT.html) 구조 분석과 레거시 논리 결함 5건 식별, 4개 탭 고도화 설계를 완료했습니다.
- 재개 — 다음 세션에서는 [구현 체크포인트](.audit/implementation.todo.md)를 읽고 Phase 1(Vite + React + TypeScript 스캐폴딩)부터 작업을 이어갑니다.

## 프로젝트 개요와 방향

- 근거 — 세션 `d29e0f2f-172e-4d05-9728-99e3dcff8b3a`에서 사용자가 MyPT의 본질적 용도를 "하루 1~2회 접속하여 추이를 기록하고 앞으로 계획을 세우는 대시보드"로 정의했습니다.
- 참고 — 실시간 운동 보조 도구(세트 간 휴식 타이머, 매 세트 개별 중량·횟수 로깅)와 수분 섭취 트래커는 배제하고, 짧은 접속 안에 상태를 갱신해 장기 추이를 조망하는 UX에 집중합니다.
- 참고 — 기존 단일 HTML 구조를 Vite + React + TypeScript + Tailwind CSS 기반 모듈형 PWA 웹앱으로 전환하며, 별도 백엔드 없이 `localStorage`와 JSON 백업·복원으로 영속성을 보장합니다.

## 기준 상태와 발견된 결함

- 근거 — 기준 파일 [MyPT.html](MyPT.html)(2,743줄)은 모든 상태를 런타임 메모리 변수에만 보관하여 페이지 새로고침 시 입력·체크 기록이 모두 초기화됩니다.
- 근거 — 저녁 간편식 세트(A/B/C)가 단일 재고 품목(`invId` 1개)만 참조하여 복합 구성품(닭가슴살·계란 등)이 차감되지 않고, 카드 잔여 횟수(`12회/8회/6회`)가 하드코딩되어 있습니다.
- 근거 — 유산소 완료 여부(`isCardioDone`)가 전역 단일 변수여서 요일 탭 전환 시 체크 상태가 초기화됩니다.
- 근거 — 11주 마일스톤의 기준점(시작 체중 91.1kg)을 여러 번 수정하면 기존 `targetW`에 오프셋이 반복 누적되어 목표 곡선이 틀어지며, 허리둘레·인바디 직접 입력 시 상단 요약이 즉시 갱신되지 않습니다.
- 근거 — 상단 헤더의 목표 구간(`91.1kg ➔ 80.8kg`)과 Tab 1 식후 소화 여유 판정 문구가 실제 슬라이더·마일스톤 값 변경에 반응하지 않고 고정되어 있습니다.

## 탭별 고도화 요약

- 참고 — **Tab 1 (저녁 일정 & 스케줄러)**: 24시간 원형 다이얼과 13시간 선형 타임라인 바에 실시간 현재 시각(Now) 마커와 진행 블록 자동 포커스를 추가하고, 평일·주말 스케줄 프로파일을 분리합니다.
- 참고 — **Tab 2 (운동 프로그램 & 중량 추이)**: 기존 휴식 타이머를 제거하고 월~일 7일 루틴 편집(CRUD), 오늘 요일 자동 선택, Tab 1 운동 시간 프리셋 연동, 루틴 카드 내 '대표 중량(kg)×횟수' 1줄 갱신 및 하단 종목별 중량·1RM 성장 추이 차트를 제공합니다.
- 참고 — **Tab 3 (식단 & 재고 관리)**: 저녁 세트(A/B/C) 다중 재고 동시 차감·복원 및 가용 횟수 동적 계산을 적용하고, 일일 식단 체크리스트 항목의 자유 편집(추가·수정·삭제)을 지원합니다.
- 참고 — **Tab 4 (11주 목표 & 히스토리)**: 체중·허리둘레·체지방률·골격근량 4대 지표 전환 차트와 일자별 운동·식단 달성 캘린더(히트맵), 전체 데이터 JSON 내보내기·불러오기 모달을 제공합니다.
